# 规则模板

规则模板是你自己写好、存在圆桌里的几份提示词。提问的时候勾上哪份，哪份就跟着这次提问一起发给每个模型。

适合放这类东西：你希望模型在某一类问题上**每次都遵守**的要求——数字要不要标出处、不要解释基础概念、用什么口径、不要做哪些事、输出成什么格式。这些话写一遍存起来，比每次在问题里重说一遍省事，也不会漏。

它和设置里的“自定义指令”是两回事：

| | 自定义指令 | 规则模板 |
|---|---|---|
| 数量 | 一份 | 很多份 |
| 什么时候带 | 每次提问都带 | 勾上才带 |
| 适合 | 对所有问题都成立的要求 | 只对某类问题成立的要求 |

两样可以同时用，模板排在自定义指令后面。

## 怎么用

入口是输入框下面那一排里的“规则模板”按钮。

- **新建**：点按钮，在弹出的菜单最下面点“新建规则模板”，起个名字，把要求写进去（可以用 Markdown），保存。新建的这份会自动勾上。
- **选用**：在菜单里点某一行就是勾上，再点一次取消。可以同时勾几份。勾了几份，按钮上会显示数字。
- **修改、删除**：菜单里每一行右边的铅笔。
- **看某一轮用了什么**：用过模板的提问，气泡下面有一个带模板名字的小标记，点开能看到发出去时的原文。

几条规矩：

- 勾上的模板对这一轮里的**所有模型**都生效，回答、互评、综合都带着。自动起对话标题的那一步不带。
- **发出去的那一刻会抄一份**。之后你再改模板、删模板，都不影响已经问过的那些轮次；对它们点“重新生成”、追加互评或综合，用的还是当时那份原文。想用新内容，重新提问。
- 勾选是跟着对话走的：一个对话记着自己上次勾了什么；开新对话时沿用眼前这份（和模型、联网开关一样）；刷新页面后取的是上一次发消息时勾的。发之前看一眼按钮上的数字。
- 导出 Markdown 时，每轮提问下面会写一行用了哪些模板（只写名字，不带原文）。

## 写的时候注意

- 模板是作为系统提示的一部分交给模型的，模型一般会照做，但**不是硬约束**。你的问题本身和模板冲突时（比如模板要求“最后附上来源”，问题里说“只回一个字”），听谁的由模型自己掂量。
- 几份模板互相矛盾时也一样，结果不可预期。同时勾的几份最好各管各的事。
- 越长越贵，也越容易被漏掉：模板算进每次请求的输入，每个模型、每一轮互评都要重新带一遍；埋在几万字里的一条要求，小模型不一定照做（测试时就遇到过）。要紧的话写短、写在前面。
- 写具体的做法，比写抽象的态度有用。“关键数字后面标出处（哪份文件、哪个期间）”比“要严谨”好使。

## 上限

| | |
|---|---|
| 最多存几份 | 50 |
| 名字 | 60 字 |
| 一份的内容 | 10000 字 |
| 一次最多勾几份 | 10 |
| 一次勾上的合计 | 64000 字节，大约两万个汉字 |

最后一条是因为系统提示是当成一个命令行参数交给 Claude Code 和 Codex 的，操作系统对单个参数的长度有上限（Linux 是 128KB）。超了会在发送时直接提示，不会发出去一半。

## 谁能看到、存在哪

- 模板存在圆桌的数据库里（`data/roundtable.db` 的 `rule_templates` 表），跟对话一起备份。
- 圆桌**没有多用户隔离**：能登录进来的人看到的是同一批模板，谁都能改能删。别往里写密码、密钥一类的东西——模板的全文会发给你选的每一个模型和它背后的服务商。
- 模板的增删改和别的接口一样要先登录。

想直接看库里存了什么：

```bash
.venv/bin/python - <<'EOF'
import sqlite3
c = sqlite3.connect("file:data/roundtable.db?mode=ro", uri=True)
for r in c.execute("select id, name, length(body) from rule_templates order by created_at"):
    print(r)
EOF
```

## 测试范围

如实说明：Claude Code 和 Codex 用真实模型验证过模板确实送到了模型手里，包括互评和综合阶段、模板改掉或删掉之后重新生成旧的一轮，以及带着接近上限（约 60KB）的模板提问；OpenRouter 走的是同一段系统提示，是在另一份代码相同的部署上验证的。界面在桌面和手机宽度下用无头 Chromium 走过一遍。**没测过**：macOS 上单个命令行参数的实际上限（那边的限制方式和 Linux 不一样）、真手机上的输入法和软键盘。
